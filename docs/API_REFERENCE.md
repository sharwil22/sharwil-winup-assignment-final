# API Reference

This reference documents the FastAPI application and HTTP contract implemented in [`backend/app`](../backend/app). Endpoint and schema behavior is based on source and [`backend/tests/test_api.py`](../backend/tests/test_api.py). For field validation and state-transition details, see [`VALIDATION_AND_STATE.md`](./VALIDATION_AND_STATE.md); for test strategy, see [`TESTING.md`](./TESTING.md).

## 1. Overview

The API supports a fictional Personal Wishes Document interview. Clients can create and read interview sessions, submit a user message, directly edit a field, and retrieve the rendered draft.

The backend is a FastAPI application (`Document Intake Assistant`, version `0.1.0`). Routes in [`backend/app/api/routes.py`](../backend/app/api/routes.py) delegate to a `SessionService`, which coordinates the domain interview flow, configured LLM provider, and session repository. Responses contain server-computed state, progress, and document preview; clients do not derive those values themselves.

### Local URL and startup

The Makefile starts the backend on port `8000`. From the repository root:

```bash
make backend
```

Equivalent command from `backend/`:

```bash
uv run uvicorn app.main:app --reload --port 8000
```

The local base URL is `http://localhost:8000`; API routes are under `/api`. FastAPI's interactive OpenAPI documentation is enabled at `/docs`, ReDoc at `/redoc`, and the OpenAPI JSON document at `/openapi.json`. The API tests verify the OpenAPI paths at `/openapi.json`.

The application defaults to the `mock` provider. Setting `LLM_PROVIDER=anthropic` selects the Anthropic provider, which requires `ANTHROPIC_API_KEY`; provider settings are defined in [`backend/app/config.py`](../backend/app/config.py).

## 2. API Conventions

### HTTP and serialization

- Request bodies are JSON (`application/json`) for message and field-edit operations.
- JSON endpoints return JSON unless otherwise noted.
- The document endpoint returns Markdown text as `text/markdown; charset=utf-8` and declares an attachment filename of `personal-wishes-draft.md`.
- The API uses Pydantic request/response models. Request models reject extra fields.
- No endpoint defines query parameters.

### Sessions and optimistic concurrency

Session IDs are generated as 32-character hexadecimal UUID values by the session store. Write operations require the caller's current `expected_version`.

The version returned as `SessionView.version` is the session revision. It starts at `0` and increments on each successful save, including message submissions and field edits. Before a write, the service checks that the supplied expected version matches the loaded session. The repository checks again under a lock at save time. A stale write returns HTTP `409` with `version_conflict`; reload the session and retry with its latest version.

The separate `WishesState.version` is a domain-state counter and is not exposed as a top-level response property. It increments only when the reducer changes the field state.

## 3. Endpoint Reference

All application routes are prefixed with `/api`.

| Method | Path | Purpose | Success |
|---|---|---|---:|
| `GET` | `/api/health` | Report selected provider and whether it is configured. | `200` |
| `POST` | `/api/sessions` | Create a new session and opening message. | `201` |
| `GET` | `/api/sessions/{session_id}` | Read the complete server-computed session view. | `200` |
| `POST` | `/api/sessions/{session_id}/messages` | Submit a user message and receive the updated turn result. | `200` |
| `PATCH` | `/api/sessions/{session_id}/fields` | Directly edit one field; the edit is treated as a correction. | `200` |
| `GET` | `/api/sessions/{session_id}/document` | Download the current generated draft as Markdown. | `200` |

There are no query parameters on these routes. `session_id` is the only path parameter where present and is a string. No route accepts an authentication credential.

### `GET /api/health`

Reports the configured provider and whether the provider is ready to make model calls. The endpoint does not make an LLM request.

**Request:** No body or parameters.

**Success response (`200`):**

```json
{
  "status": "ok",
  "provider": "mock",
  "model_configured": true
}
```

`provider` is one of `mock` or `anthropic`. `model_configured` is a boolean; for Anthropic it reflects whether a non-empty API key is configured.

### `GET /api/sessions/{session_id}`

Returns the current `SessionView`, identical in structure to the successful response from `POST /api/sessions`, with current fields, messages, document, progress, focus, and version.

**Request:**

- Path parameter `session_id` (string, required).
- No body or query parameters.

**Success response (`200`):** `SessionView`, as in the create-session response above.

**Errors:** Unknown ID returns `404 session_not_found`.

### `POST /api/sessions/{session_id}/messages`

Submits one user message. The server trims surrounding whitespace, obtains an extraction from the selected provider, validates and reduces proposed updates, plans the next question, appends the user/assistant messages, and saves the session.

**Path parameter:** `session_id` (string, required).

**Request body (`PostMessage`):**

| Field | Type | Required | Constraints |
|---|---|---:|---|
| `content` | string | Yes | Length 1–2000 inclusive; whitespace-only text is also rejected by the route after trimming. |
| `expected_version` | integer | Yes | Must be greater than or equal to 0. |

Extra body properties are forbidden.

**Valid request example:**

```json

  "expected_version": 0
}
```

**Success response (`200`):** `TurnResult`, which includes all `SessionView` properties plus:

| Field | Type | Meaning |

| `reply` | string | Assistant reply for this turn. |
| `changes` | array of `ChangeView` | State changes made during this turn. |
| `rejected_updates` | array of `RejectedUpdateView` | Proposed field updates rejected by semantic validation. |

**Errors:**

- `404 session_not_found`: no session has that ID.
- `409 version_conflict`: `expected_version` is stale.
- `422 validation_error`: invalid request body or blank trimmed content.
- `503 llm_not_configured`: selected provider lacks required configuration.
- `503 llm_unavailable`: provider is temporarily unavailable.
- `500 internal_error`: unexpected unhandled server error.

Malformed model output or model refusal is handled by the interview service and ordinarily returns a successful `200` turn with unchanged field state, a planner fallback reply, and warning codes; it is not the same as an unavailable provider.

### `PATCH /api/sessions/{session_id}/fields`

Edits one field directly. The service treats the edit as a correction, validates it, applies the reducer, and saves the updated session. Chat evidence is not required for this UI-originated update.

**Path parameter:** `session_id` (string, required).

**Request body (`PatchField`):**

| Field | Type | Required | Constraints |
|---|---|---:|---|
| `path` | string enum | Yes | One of the nine `FieldPath` values listed below. |
| `value` | boolean, string, array of strings, or array of gift objects | Yes | Semantic validation depends on `path`. |
| `expected_version` | integer | Yes | Must be greater than or equal to 0. |

Gift objects have required string properties `item` and `recipient`; extra properties are forbidden. Extra top-level body properties are also forbidden.

Supported `path` values: `full_name`, `home_address`, `covers_worldwide_assets`, `has_children`, `children_names`, `executor.name`, `executor.relationship`, `specific_gifts`, `additional_wishes`.

**Valid request example (edit a text field):**

```json
{
  "path": "full_name",
  "value": "Jane A. Smith",
  "expected_version": 1
}
```

**Valid gift edit example:**

```json
{
  "path": "specific_gifts",
  "value": [
    {
      "item": "piano",
      "recipient": "Ann"
    }
  ],
  "expected_version": 1
}
```

**Success response (`200`):** `SessionView` with the updated state. It does not include the `TurnResult`-only `reply`, `changes`, `rejected_updates`, or `warnings` properties.

**Errors:**

- `404 session_not_found`: no session has that ID.
- `409 version_conflict`: `expected_version` is stale.
- `422 validation_error`: invalid request body, unknown `path`, or a value rejected by field-specific semantic validation.
- `500 internal_error`: unexpected unhandled server error.

### `GET /api/sessions/{session_id}/document`

Returns the current rendered draft for the session.

**Request:**

- Path parameter `session_id` (string, required).
- No body or query parameters.

**Success response (`200`):** Markdown document bytes with `Content-Type: text/markdown; charset=utf-8` and `Content-Disposition: attachment; filename="personal-wishes-draft.md"`.

Example response body:

```markdown
> **FICTIONAL DRAFT — NOT LEGAL ADVICE.**

I, Jane Smith, of [To be confirmed: home address], make this Personal Wishes Document.
...
```

The ellipsis is illustrative prose, not literal API output. The complete text is rendered from the current session state.

**Errors:** Unknown session returns `404 session_not_found`.

## 4. Request and Response Schemas

The public request and response DTOs are defined in [`backend/app/api/schemas.py`](../backend/app/api/schemas.py).

### Request models

| Model | Properties |
|---|---|
| `PostMessage` | `content` (required string, 1–2000 chars), `expected_version` (required integer, minimum 0). |
| `GiftIn` | `item` and `recipient` (required strings). |
| `PatchField` | `path` (required `FieldPath`), `value` (required union of bool/string/string-array/gift-array), `expected_version` (required integer, minimum 0). |

Request models inherit configuration `extra="forbid"`; clients should not send undeclared properties. In addition to Pydantic constraints, message handling trims content and rejects content that is blank after trimming.

`FieldPath` is the literal set:

```text
full_name
home_address
covers_worldwide_assets
has_children
children_names
executor.name
executor.relationship
specific_gifts
additional_wishes
```

Semantic field validation is stricter than the union accepted by `PatchField.value`. For example, a string is not a valid semantic value for `has_children`, and gifts require both non-empty `item` and `recipient`. See [`backend/app/domain/validation.py`](../backend/app/domain/validation.py) for the complete rules.

### Response models

#### `HealthResponse`

- `status`: literal string `"ok"`
- `provider`: `"mock"` or `"anthropic"`
- `model_configured`: boolean

#### `SessionView`

- `id`: session ID string
- `version`: integer session revision
- `fields`: array of `FieldView`, in the server's interview order
- `state`: plain confirmed-value object; candidate values are not exposed through this flattened object
- `messages`: conversation message array
- `document_markdown`: server-rendered draft string
- `progress`: `ProgressView`
- `is_complete`: boolean
- `focus`: `FieldPath` or `null`
- `next_question`: string

#### `FieldView`

Each field object includes `path`, `label`, `value`, `status`, `candidate`, `note`, `source`, `source_turn`, `evidence`, and `previous_value`.

- `status` is one of `missing`, `needs_clarification`, `captured`, or `not_applicable`.
- `value` and `candidate` are field-specific JSON values or `null`.
- `note` is nullable text.
- `source` is nullable `chat` or `edit`.
- `source_turn` is nullable integer (1-based user turn).
- `evidence` is nullable text.
- `previous_value` may be null or a JSON value; the API only exposes provenance fields and previous value when the field is currently `captured`.

#### Related response structures

- `MessageView`: `role` (`user` or `assistant`) and `content` string.
- `ProgressView`: integer `completed` and `total`.
- `ChangeView`: `path`, `label`, `old_value`, `new_value`, `old_status`, `new_status`.
- `RejectedUpdateView`: `path` and `reason`.
- `TurnResult`: `SessionView` plus `reply`, `changes`, `rejected_updates`, and `warnings`.

The server computes progress as fields in `captured` or `not_applicable` status out of the total nine field paths. Only `POST .../messages` returns the `TurnResult` additions.

## 5. Error Handling

Errors handled by the application use this JSON envelope:

```json
{
  "error": {
    "code": "version_conflict",
    "message": "This session changed in another request. Reload it and try again.",
    "retryable": true
  }
}
```

`retryable` is a boolean. The actual registered error handlers are in [`backend/app/api/errors.py`](../backend/app/api/errors.py).

| HTTP | Code | When returned | Retryable |
|---:|---|---|---:|
| `404` | `session_not_found` | A requested session ID does not exist. | `false` |
| `409` | `version_conflict` | A write uses a stale expected version or loses the save-time concurrency check. | `true` |
| `422` | `validation_error` | Pydantic request validation fails, message content is blank after trimming, or a field edit fails semantic validation. | `false` |
| `503` | `llm_not_configured` | An LLM operation is attempted without required provider configuration. | `false` |
| `503` | `llm_unavailable` | The configured provider reports temporary unavailability. | `true` |
| `500` | `internal_error` | An unexpected unhandled exception occurs. Internal details are logged, not returned. | `false` |

`LLMRefused` and malformed model output are handled within the interview service rather than returned as these error statuses: refusals leave field state unchanged and produce a fallback turn; malformed output is retried once and then produces a fallback turn if still malformed. The session can still record that user/assistant exchange when the service successfully returns an outcome.

## 6. Example API Workflows

Examples use `http://localhost:8000` as the base URL and illustrative values. Replace `{session_id}` with the actual `id` returned by session creation. Carry forward the latest `version` returned by each successful write.

### 1. Create a session

```bash
curl -sS -X POST http://localhost:8000/api/sessions
```

Returns `201` and a `SessionView`. Copy its `id` and `version` (initially `0`).

### 2. Submit a user message

```bash
curl -sS -X POST \
  http://localhost:8000/api/sessions/{session_id}/messages \
  -H 'Content-Type: application/json' \
  -d '{"content":"My name is Jane Smith.","expected_version":0}'
```

Returns `200` and a `TurnResult`; use its updated top-level `version` for the next write.

### 3. Read session state

```bash
curl -sS http://localhost:8000/api/sessions/{session_id}
```

Returns a `SessionView`, including all fields, plain confirmed state, messages, progress, draft preview, focus, and next question. There is no separate state-only endpoint.

### 4. Edit a field

```bash
curl -sS -X PATCH \
  http://localhost:8000/api/sessions/{session_id}/fields \
  -H 'Content-Type: application/json' \
  -d '{"path":"full_name","value":"Jane A. Smith","expected_version":1}'
```

Returns `200` and the updated `SessionView`. The `expected_version` here must be the current version from the last response, not necessarily `1` in a real workflow.

### 5. Retrieve the generated draft

```bash
curl -sS -D - \
  http://localhost:8000/api/sessions/{session_id}/document
```

Returns `200` with Markdown content and an attachment disposition. Alternatively, the current draft preview is already present as `document_markdown` in `SessionView`.

## 7. Concurrency and State Management

The client sends `expected_version` on both write endpoints. The service first compares it with the loaded session version. Message submission then performs model/domain work; the repository checks again while holding its lock before saving. A competing save causes HTTP `409 version_conflict`, so a write based on stale state does not silently overwrite a newer session.

Successful saves increment `Session.version` once. The message handler may independently increment the internal `WishesState.version` when the reducer changes field state; this domain counter is not the concurrency token sent to clients.

The default `InMemorySessionRepository` stores snapshots in process memory. Sessions are not durable across process restarts, and the lock is not a distributed coordination mechanism. The `SessionRepository` protocol allows an alternate repository to be supplied when constructing the app, but the default runtime wiring in [`backend/app/main.py`](../backend/app/main.py) selects the in-memory implementation.

## 8. Authentication, Security, and Limitations

Authentication and authorization are not implemented in these routes. There is no user identity or ownership check associated with a session ID, so possession of an ID is sufficient to address that session in the current process.

Additional implementation limits relevant to API clients:

- Default session storage is volatile in-memory storage.
- Selecting the Anthropic provider requires an external API key and may result in provider charges; the `mock` provider does not require a key.
- Evidence checking and the field state machine are application-level safeguards, not an authorization or identity system.
- The output is a fictional Personal Wishes Document draft and is not a legally valid document or legal advice. It is not a medical chatbot API.
- The endpoint accepts message content up to 2000 characters. This limit applies to the HTTP request schema.

## 10. Mermaid Request Lifecycle Diagram

The diagram shows message submission. Read, health, document, and direct-edit endpoints do not call the LLM; direct edits use the same validation/reducer path but create a correction proposal from the request.

```mermaid
sequenceDiagram
    actor Client
    participant FastAPI as FastAPI route
    participant Service as SessionService
    participant Store as SessionRepository
    participant Provider as LLM provider
    participant Domain as Validation / reducer / planner

    Client->>FastAPI: POST /api/sessions/{id}/messages (content + expected_version)
    FastAPI->>Service: send_message(id, content, expected_version)
    Service->>Store: get(id)
    Store-->>Service: Session snapshot
    Service->>Service: Check expected_version
    Service->>Provider: extract(TurnContext)
    Provider-->>Service: TurnExtraction
    Service->>Domain: Convert proposals and validate updates
    Domain->>Domain: Reduce accepted updates
    Domain->>Domain: Select next focus and compose reply
    Domain-->>Service: TurnOutcome
    Service->>Service: Append messages and change log
    Service->>Store: save(updated_session, expected_version)
    Store->>Store: Check version under lock and increment
    Store-->>Service: Saved Session
    Service-->>FastAPI: Session + TurnOutcome
    FastAPI-->>Client: 200 TurnResult

    Note over Service,Store: A stale initial or save-time version check returns 409.
    Note over Provider,Domain: Provider configuration/unavailability may return 503; malformed/refused output is handled as a fallback turn.
```
